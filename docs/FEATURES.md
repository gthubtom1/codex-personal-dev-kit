# Feature Map

This is the current behavior of Codex Personal Dev Kit. It is an index, not a development log.

| ID | User capability | Entry points / connected path | Expected result | Verification | Criticality | Status |
| --- | --- | --- | --- | --- | --- | --- |
| DK-001 | Start software work with one plain-language request | Global AGENTS route -> `codex-development-assistant` -> requirement expansion -> persistent Goal for explicit multi-step completion requests | Codex expands the need and continues to a usable, verified result with only material decisions exposed; the user need not name Skills or Goal. | Official validation of all seven Skills plus entry/Goal forward scenarios | critical | active |
| DK-002 | Create and open independent long-term projects | Mother folder -> `create-project.ps1` -> project template -> local Git baseline -> open project folder | Each `projects/<name>` folder is an independent Codex working folder and Git repository; the mother folder only manages projects and never continues an existing project's development. | `test_workspace_scripts.py` | critical | active |
| DK-003 | Change one feature without silently losing another | Aggregated FEATURES IDs -> current change contract -> mid-task `declare-change` when scope expands -> guard-managed staging -> executed verification commands/content fingerprint -> standalone commit -> Hooks | Protected records, undeclared scope changes, undeclared deletions, mixed user changes, fabricated evidence, composite commits, and post-verification code changes are stopped. | `test_feature_guard.py` | critical | active |
| DK-004 | Recover from mistakes without learning Git first | Safe development Skill -> explicit task path staging -> exact-tree local checkpoints -> Rules/PreToolUse guard | Local work has trustworthy recovery points while destructive/remote Git, global installs, publish, deploy, and infrastructure commands are blocked or require user action. | `test_feature_guard.py`, `test_pre_tool_guard.py`, and Codex execpolicy parser checks | critical | active |
| DK-005 | Continue across shorter Codex tasks without giant documents | startup/resume/compact/clear recovery packet -> AGENTS/PROJECT/FEATURES/STATUS -> Git/tests -> continuity Skill -> generic docs audit | Recovery preserves a bounded `Next Action`, verified-but-uncommitted work remains protected, and any oversized text document under `docs/` is reported without relying on its filename. | `test_feature_guard.py`, `test_audit_project.py`, and continuity forward scenario | standard | active |
| DK-006 | Use native subagents without creating task or merge chaos | Orchestration Skill -> collaboration `spawn_agent`/`wait_agent` -> read-only specialists -> one writer per checkout -> Worktree only for real isolation | Parallel research, review, and verification return concise evidence to the current task; no user-visible task, chat, fork, cross-task message, or Handoff is created as a substitute for a subagent. | Orchestration routing tests and native-subagent forward scenario | standard | active |
| DK-007 | Validate and install the assistant predictably | Local-or-Git Marketplace metadata -> runnable Codex CLI -> preview/apply/backup -> HEAD/worktree/version/plugin-state diagnostics | Local sources install without `--ref` but are pinned to a clean real HEAD; Git sources require a fixed ref; diagnosis detects drift and installed-version mismatch. | `test_install_scripts.py`, Codex execpolicy checks, and Plugin validator | standard | active |

Keep this file concise. Add a feature only when it is a stable user capability with a repeatable verification path.
