# Feature Map

This is the current behavior of Codex Personal Dev Kit. It is an index, not a development log.

| ID | User capability | Entry points / connected path | Expected result | Verification | Criticality | Status |
| --- | --- | --- | --- | --- | --- | --- |
| DK-001 | Start software work with one plain-language request | Global AGENTS route -> `codex-development-assistant` -> requirement expansion -> automatic Git readiness -> persistent Goal for explicit multi-step completion requests | Codex expands the need and continues to a usable, verified, locally recoverable result with only material decisions exposed; the user need not name Skills, Goal, or Git. | Official validation of all seven Skills plus entry/Goal/recovery forward scenarios | critical | active |
| DK-002 | Create and open independent long-term projects | Configurable mother folder or existing-project onboarding -> path-templated rules/config -> installed central runtime Hook path -> generated/path/content secret preflight -> local Git baseline -> open project folder | Each project is an independent Codex working folder and Git repository with a first local recovery point; existing source is preserved, custom workspace roots resolve correctly, project Hooks prefer the installed central runtime, known secret files stay ignored, and suspicious credential content stops the baseline. | `test_workspace_scripts.py` | critical | active |
| DK-003 | Change one feature without silently losing another | Aggregated FEATURES IDs -> current change contract -> native apply_patch/Edit/Write and shell mutation Hooks -> guard-managed staging -> executed verification/content fingerprint -> mandatory guard checkpoint | Protected records, undeclared scope/deletions, mixed user changes, fabricated evidence, raw commits, all native file-edit paths, post-verification changes, and verified-but-unsaved completion are stopped. | `test_feature_guard.py` | critical | active |
| DK-004 | Recover from mistakes without learning Git first | Safe development Skill -> current branch -> mandatory exact-tree checkpoints -> clean-worktree reversible rollback -> Rules/PreToolUse guard | Every verified slice becomes a local recovery point without version branches; “return to the previous version” creates a new recovery commit while destructive/remote actions remain blocked. | `test_feature_guard.py`, `test_pre_tool_guard.py`, `test_workspace_scripts.py`, and Codex execpolicy parser checks | critical | active |
| DK-005 | Continue across shorter Codex tasks without giant documents | startup/resume/compact/clear recovery packet -> AGENTS/PROJECT/FEATURES/STATUS -> Git/tests -> continuity Skill -> generic docs audit | Recovery preserves a bounded `Next Action`, verified-but-uncommitted work remains protected, and any oversized text document under `docs/` is reported without relying on its filename. | `test_feature_guard.py`, `test_audit_project.py`, and continuity forward scenario | standard | active |
| DK-006 | Use native subagents without creating task or merge chaos | Orchestration Skill -> native collaboration `spawn_agent`/`wait_agent` -> read-only specialists -> one writer per checkout -> Worktree only for real isolation -> non-interference validator | Parallel work returns concise evidence to the current task; Hooks do not intercept Agent tools, no replacement MCP/App protocol exists, and no visible task, chat, fork, message, or Handoff substitutes for a subagent. | `test_orchestration_routing.py`, structural validator, and native-subagent forward scenario | standard | active |
| DK-007 | Validate and install the assistant predictably | Fixed clean local checkout -> all-market installed-Plugin query + legacy migration preview -> managed-marker preflight -> prepare/verify standalone -> exact backup/selective Hook cleanup/Plugin removal -> metadata-driven update -> source/version/native-capability diagnostics | Standalone mode is primary, preserves unrelated global AGENTS and Hook content, rejects damaged managed markers, detects old Plugin state without metadata or on custom Marketplaces, prepares the complete replacement before switching legacy state, remembers custom workspace roots during updates, refuses unsafe old/new stacking, installs no replacement native capability, pins the real source HEAD, and leaves the optional Plugin as a Skills-only package. | `test_install_scripts.py`, structural checks, Skill validators, optional Plugin validator, and Codex execpolicy checks | standard | active |

Keep this file concise. Add a feature only when it is a stable user capability with a repeatable verification path.
