# Feature Map

This is the current behavior of Codex Personal Dev Kit. It is an index, not a development log.

| ID | User capability | Entry points / connected path | Expected result | Verification | Criticality | Status |
| --- | --- | --- | --- | --- | --- | --- |
| DK-001 | Start software work with one plain-language request | Global AGENTS route -> `codex-development-assistant` -> requirement expansion -> automatic Git readiness -> persistent Goal for explicit multi-step completion requests | Codex expands the need and continues to a usable, verified, locally recoverable result with only material decisions exposed; the user need not name Skills, Goal, or Git. | Official validation of all seven Skills plus entry/Goal/recovery forward scenarios | critical | active |
| DK-002 | Create and open independent long-term projects | Configurable mother folder or existing-project onboarding -> path-templated AGENTS/config/docs -> generated/path/content secret preflight -> local Git baseline -> open project folder | Each project is an independent Codex working folder and Git repository with a first local recovery point; existing source is preserved, custom workspace roots resolve correctly, lifecycle Hooks are not installed, known secret files stay ignored, and suspicious credential content stops the baseline. | `test_workspace_scripts.py` | critical | active |
| DK-003 | Change one feature without silently losing another | Aggregated FEATURES IDs -> current change contract -> explicit guard-managed staging -> executed verification/content fingerprint -> checkpoint | Protected records, undeclared scope/deletions, mixed user changes, fabricated evidence, raw commits, post-verification changes, and verified-but-unsaved completion are detected by the explicit guard workflow. | `test_feature_guard.py` | critical | active |
| DK-004 | Recover from mistakes without learning Git first | Safe development Skill -> current branch -> exact-tree checkpoints -> clean-worktree reversible rollback -> explicit guard scripts | Every verified slice gets a local recovery point without version branches; “return to the previous version” creates a new recovery commit while destructive/remote actions remain blocked. | `test_feature_guard.py`, `test_pre_tool_guard.py`, and `test_workspace_scripts.py` | critical | active |
| DK-005 | Continue across shorter Codex tasks without giant documents | startup/resume/compact/clear recovery packet -> AGENTS/PROJECT/FEATURES/STATUS -> Git/tests -> continuity Skill -> generic docs audit | Recovery preserves a bounded `Next Action`, verified-but-uncommitted work remains protected, and any oversized text document under `docs/` is reported without relying on its filename. | `test_feature_guard.py`, `test_audit_project.py`, and continuity forward scenario | standard | active |
| DK-006 | Use native subagents without creating task or merge chaos | Orchestration Skill -> native collaboration `spawn_agent`/`wait_agent` -> user-selected Sol/Luna roster -> one writer per checkout -> Worktree only for real isolation -> non-interference validator | Multiple bounded subagents can run in parallel; default is Luna/max, explicit Sol/Luna counts are honored at max, no Hook or replacement MCP/App protocol intercepts native tools, and no visible task substitutes for a subagent. | `test_orchestration_routing.py`, structural validator, and native-subagent forward scenario | standard | active |
| DK-007 | Validate and install the assistant predictably | Fixed clean local checkout -> managed-marker preflight -> prepare/verify standalone -> metadata-driven update -> source/version/native-capability diagnostics; optional legacy cleanup only when explicitly requested | Standalone mode is primary, preserves unrelated global AGENTS and user Hook content, merges required native subagent defaults into existing workspace/project config without locking the main model, rejects damaged managed markers, can detect and migrate old Plugin/custom-agent state without installing a replacement, remembers custom workspace roots during updates, pins the real source HEAD, and leaves native Codex capabilities untouched. | `test_install_scripts.py`, `test_workspace_scripts.py`, structural checks, and Skill validators | standard | active |

Keep this file concise. Add a feature only when it is a stable user capability with a repeatable verification path.
