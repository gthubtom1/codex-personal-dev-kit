# 项目文档生命周期

| 文件 | 保存内容 | 建议预算 | 更新方式 |
| --- | --- | --- | --- |
| `AGENTS.md` | 命令、规则、验证和文档路由 | 小于 8 KiB | 只加入反复出现的规则 |
| `README.md` | 项目用途、安装、启动、测试 | 保持当前 | 行为变化时更新 |
| `PROJECT.md` | 用户、目标、范围、非目标 | 小于 200 行 | 产品边界改变时更新 |
| `FEATURES.md` | 当前用户能力和验证入口 | 主索引小于 250 行 | 行为变化时更新，按稳定领域拆分 |
| `ROADMAP.md` | 当前和接下来 2 到 3 个里程碑 | 小于 150 行 | 完成项删除或归档到 Git |
| `ARCHITECTURE.md` | 当前模块、依赖、接口和数据流 | 小于 300 行 | 真实架构变化时更新，过长按领域拆分 |
| `STATUS.md` | 当前里程碑、验证、问题、下一步 | 100 到 150 行 | 每次交接覆盖更新 |
| `.codex/active-plan.md` | 当前复杂任务尚未完成的步骤 | 单个临时文件 | Git 忽略，任务完成后删除 |
| `docs/adr/INDEX.md` | 当前 ADR 的标题、状态、领域和替代关系 | 小型索引 | ADR 增删或状态变化时更新 |
| `docs/adr/` | 重大且难逆转的决定 | 一项一个文件 | 创建后只更新状态或替代关系 |
| `RUNBOOK.md` | 部署、备份、恢复、故障处理 | 按实际需要 | 上线或运维流程变化时更新 |

## 不保存

- 聊天全文、模型推理、完整 diff、完整测试日志。
- 每日流水账、已完成任务的重复摘要。
- 能从代码、测试或 Git 直接得到的冗余副本。
- 没有决策价值的临时方案列表。
- `plan-v2.md`、`session-summary.md`、`development-log.md` 等按任务累计的永久文件。

## 超预算处理

1. 删除过期状态和重复说明。
2. 把历史交给 Git，不另建永久日志。
3. 功能和架构按稳定业务领域拆分，并在主文件建立短索引。
4. 仍过长时检查是否混入运行手册、需求或任务计划。

ADR 数量增加时维护 `docs/adr/INDEX.md`，在索引中标记 accepted、superseded 或 retired。不要把所有 ADR 合并成一个巨型历史文件。
