# 上下文与任务边界

## 继续当前任务

- Goal 和交付物没有改变。
- 新信息直接帮助解决同一问题。
- 当前推理链仍有价值，噪声可通过简短状态回顾或压缩处理。

## 开启新任务

- 开始新的功能、里程碑、分支或独立交付物。
- 当前任务已经完成，只剩后续改进。
- 对话充满大量日志、反复试验或多次压缩，关键事实难定位。
- 需要独立权限、Worktree、长期 Goal 或不同专业上下文。

## 使用子代理

- 当前任务内部有有界且可并行的探索、测试或审查。
- 结果应回到主任务立即整合。
- 不需要长期保留独立上下文。

## 恢复顺序

1. `AGENTS.md`、当前 Goal 和未完成的 `.codex/current-change.json`。
2. `PROJECT.md`、`FEATURES.md`、`STATUS.md` 和相关架构章节。
3. Git 状态、当前分支和最近少量提交。
4. 必要代码、测试和运行结果。
5. 旧任务或本地 memory 只在仍有缺口时使用。

## 控制上下文污染

- 原始日志保存在工具输出或临时文件，只向主任务返回摘要。
- 大文件先搜索符号和局部读取。
- 完成的探索结论进入代码、测试或当前文档，不重复粘贴。
- 同一错误连续重复时停下来重审假设和环境。
