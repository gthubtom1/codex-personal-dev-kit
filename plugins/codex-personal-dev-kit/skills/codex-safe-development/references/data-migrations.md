# 数据迁移

数据库结构、文件格式和历史数据变化必须可分阶段、可观测、可回滚。

## 计划

1. 描述当前结构、目标结构、数据量、停机约束和兼容窗口。
2. 选择 expand-migrate-contract：先加兼容结构，再迁移数据，最后移除旧结构。
3. 定义备份、恢复、校验、批次、限速、重试和幂等策略。
4. 说明旧版本应用与新结构能否共存。
5. 数据删除和不可逆变换需要用户明确许可。

## 实施

- 迁移脚本纳入版本控制并可在测试数据上重复运行。
- 大表或大量文件分批处理，记录游标和进度。
- 写入前后校验数量、约束、哈希或业务不变量。
- 先在隔离环境演练失败恢复。
- 生产迁移、回填和清理只准备命令与运行手册，不由 AI 自动执行。

## 回滚

回滚不能只写“恢复备份”。明确触发条件、负责者、恢复时间、应用版本和迁移中间状态的处理方式。
