# 依赖与供应链

## 新增前

1. 说明现有代码或标准库为什么不足。
2. 比较维护状态、版本兼容、许可证、体积、安全记录和退出成本。
3. 区分开发依赖与生产依赖。新增生产依赖必须先获用户许可。
4. 优先使用项目已有框架和已锁定生态，不为小问题引入大平台。

## 修改时

- 使用项目既有包管理器和锁文件。
- 不混用 npm/pnpm/yarn 或多个 Python 锁定方案。
- 只更新必要版本，避免顺便全量升级。
- 审查安装脚本、原生二进制和新传递依赖。
- 运行受影响测试和构建，记录锁文件变化原因。

## 全局工具

- 默认优先项目本地依赖。确实需要 Windows 全局工具时，先获得 package ID、精确版本和 `user`/`machine` scope 授权。
- 授权后由 AI 运行 Skill 自带的 `scripts/install_global_tool.py`。当前只支持官方 winget source 的首次精确安装：先 `show` 核对、拒绝隐式升级/降级、安装后再 `list` 验证。
- 原始 winget/choco/scoop 命令、未固定版本、自动替换包管理器、升级/降级和下载替代安装器仍禁止。

## 禁止原始执行

- 未授权或不经过上述 guarded installer 的全局安装、升级、降级或系统包修改。
- 向公共 registry 发布包。
- 注入长期凭据或把 token 写入配置。
- 在不了解破坏性变化时执行大版本升级。
