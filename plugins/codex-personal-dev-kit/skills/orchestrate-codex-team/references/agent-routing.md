# 原生子代理路由

## 选择边界

- 单代理：一个模块、清晰结果、低风险改动。
- 原生子代理：多个有界、可独立完成的探索、资料、测试或审查流。
- Worktree：两个写入任务确实需要隔离，或者计划任务必须远离当前未完成工作。

## 官方默认

- Dev Kit 不写入或修改任何子代理模型、推理强度、并发数、启用开关或中断行为设置。
- 使用原生 `spawn_agent` 时不传这些覆盖参数；当前 Codex 任务如何选择模型、推理和容量完全由官方运行时与用户已有配置决定。
- 当前任务未提供 `spawn_agent`、参数被拒绝或启动失败时如实报告；不得安装 Plugin/Hook/自定义 Agent、修改配置或创建可见任务来模拟成功。

## 临时账本

每次编排只在当前主任务内存中记录编号、任务、任务接收确认、状态和结果摘要。能力不可用、启动失败、超时和中断必须保留，不能静默补位。

- `spawn_agent` 是核心启动能力，`list_agents` 只是可选状态信息。并发和排队以原生工具实际接受情况为准。
- 启动后要求子代理确认任务正文可读、范围正确。确认失败时补充一次，仍失败就停止并报告。
- 缺少 `list_agents` 不等于子代理不可用；缺少等待、follow-up 或 interrupt 时只启动短时只读任务。

## 写入隔离

- 默认只有主代理写源码。
- 只读子代理可以共享 checkout。
- 两个写入任务必须使用不同 Worktree、分支和文件所有权，并由主代理按明确顺序整合。
