# 原生子代理路由

## 名词边界

- 子代理/subagent：当前 Codex 任务内部由 collaboration `spawn_agent` 启动的原生代理。
- Codex 任务/聊天：侧边栏中用户可见、拥有独立长期上下文的任务。
- 两者不能互相替代。用户说“启动子代理”时，不得创建、分叉、转发或 Handoff 到可见任务。

## 复杂度分级

| 级别 | 特征 | 默认方式 |
| --- | --- | --- |
| S | 单文件、明确行为、低风险 | 主代理直接完成 |
| M | 数个文件、需要定位和测试 | 主代理，必要时 1 个只读探索者 |
| L | 跨模块、方案取舍、多个验证面 | 2 到 3 个只读子代理，主代理单独写入 |
| XL | 多个调查面、长期迁移或确需并行实现 | 主任务分阶段，原生子代理并行只读；并行写入才使用独立 Worktree |

## 选择子代理

只有满足至少一个条件才启动：

- 两个以上调查可以真正并行。
- 需要独立安全、正确性或测试审查。
- 大量日志、文档或代码搜索会污染主任务上下文。
- 需要与主代理结论隔离的前向验证。

不要为简单编辑、顺序依赖工作或同一小文件启动多个代理。

## 模型门禁

- 主对话模型由用户选择，不由本路由固定。
- 默认子代理为 `gpt-5.6-luna`、推理强度 `max`；允许同时运行多个，最多到配置中的并发上限。
- 用户明确指定 Sol/Luna 数量时，按精确数量和模型调用，每个子代理都必须是 `max`；总数超过并发上限时分波次执行，保持精确总数，不静默减少。
- 调用前确认当前原生模型目录支持请求的模型和 `max`；不可用时不得静默降级、换模型或减少数量。
- 角色只是任务职责，不使用自定义 Agent 文件替代原生 per-call 模型选择，除非用户明确要求持久命名代理。

## 角色边界

- Explorer：定位入口、调用链、数据流和影响面，只读。
- Architect：比较模块边界、接口、迁移和可逆性，只读。
- Reviewer：查找真实 bug、安全、兼容和测试缺口，只读。
- Verifier：运行已约定检查，保存最少证据，不修改产品源码。
- Worker：实现一个明确切片；默认由主代理承担。并行 Worker 必须在独立 Worktree。

## 子代理与新任务

- 用户明确说“子代理”“subagent”或要求若干代理并行回答：使用 `spawn_agent`，结果回到当前任务汇总。
- 当前成果内几分钟到一小时的有界调查、测试或审查：使用原生子代理。
- 当前成果完成后需要新的长期上下文：建议用户开启新任务并提供简短交接提示。
- 只有用户明确要求创建、分叉、交接或操作另一个 Codex 任务时，才调用任务/聊天管理工具。
- 不得把 `create_thread`、`fork_thread`、`send_message_to_thread` 或 `handoff_thread` 当成子代理接口。

## 写入所有权

- 一个 checkout 同时只有一个源码写入者。
- 并行写入前声明 Worktree、分支、拥有文件和集成顺序。
- 子代理不得提交主代理未审查的合并结果。
- 共享数据库、生成目录和开发服务器也视为可变资源，需要单一所有者。
