# 代理与任务路由

## 复杂度分级

| 级别 | 特征 | 默认方式 |
| --- | --- | --- |
| S | 单文件、明确行为、低风险 | 主代理直接完成 |
| M | 数个文件、需要定位和测试 | 主代理，必要时 1 个只读探索者 |
| L | 跨模块、方案取舍、多个验证面 | 2 到 3 个只读子代理，主代理单独写入 |
| XL | 多个独立成果、长期迁移或可并行实现 | 多任务和独立 Worktree，每个任务有自己的 Goal |

## 选择子代理

只有满足至少一个条件才启动：

- 两个以上调查可以真正并行。
- 需要独立安全、正确性或测试审查。
- 大量日志、文档或代码搜索会污染主任务上下文。
- 需要与主代理结论隔离的前向验证。

不要为简单编辑、顺序依赖工作或同一小文件启动多个代理。

## 角色边界

- Explorer：定位入口、调用链、数据流和影响面，只读。
- Architect：比较模块边界、接口、迁移和可逆性，只读。
- Reviewer：查找真实 bug、安全、兼容和测试缺口，只读。
- Verifier：运行已约定检查，保存最少证据，不修改产品源码。
- Worker：实现一个明确切片；默认由主代理承担。并行 Worker 必须在独立 Worktree。

## 多任务与子代理

- 新成果、新 Goal、新分支或需要数天独立推进：新任务。
- 当前成果内几分钟到一小时的有界调查：子代理。
- 需要共享当前推理和立即汇总：子代理。
- 需要长期保留独立上下文：多任务。

## 写入所有权

- 一个 checkout 同时只有一个源码写入者。
- 并行写入前声明 Worktree、分支、拥有文件和集成顺序。
- 子代理不得提交主代理未审查的合并结果。
- 共享数据库、生成目录和开发服务器也视为可变资源，需要单一所有者。
