# Orchestrate Codex Team

主任务持有需求、范围和最终决策。这里的“子代理”只指 Codex 当前任务内部、由原生 collaboration 工具管理的 subagent。

## 原生边界

- 用户要求启动子代理时，直接使用当前任务提供的 `spawn_agent`；需要等待、补充任务或停止时使用原生 wait、message、follow-up 或 interrupt 工具。
- 不得使用可见 Codex 任务、Plugin、Hook、MCP、自定义 Agent 或永久通信文件模拟子代理。
- Dev Kit 不写入、合并、迁移或建议任何 `[agents]`、`multi_agent`、子代理模型、推理强度、并发数和中断行为设置。
- 调用 `spawn_agent` 时不传模型、推理强度或并发覆盖，让当前 Codex 任务使用官方默认行为和用户自己已有的配置。
- 当前任务没有 `spawn_agent`、参数被拒绝或启动失败时，如实说明原生能力在本次环境不可用；不得修改配置或换一种机制冒充成功。
- 简单工作由主代理完成。子代理只承担有界独立探索、官方资料核对、测试、架构/安全/回归审查或答案盲测。

## 账本和监督

只在主任务内存中维护临时账本：代理编号、任务、是否确认收到任务、状态（`queued`、`running`、`completed`、`failed`、`interrupted` 或 `timeout`）和精炼结果。不要把子代理日志或转录写进项目文档。

- `spawn_agent` 是启动能力；`list_agents` 只是可选状态信息。并发、排队、模型和推理由原生工具实际接受结果决定，Dev Kit 不设置上限或默认值。
- 启动后先确认子代理收到并理解了任务。任务正文缺失、不可读或范围错误时补充一次，仍无法确认就停止该代理并报告。
- 缺少等待、follow-up 或 interrupt 时，只启动短时、有界、只读的任务，并报告监督能力受限。
- 等待、跟进和中断完全使用当前 Codex 原生工具的官方行为；Dev Kit 不规定心跳、超时、重试或强制中断参数。
- 汇总时区分计划、启动、完成、失败、中断和超时；失败或超时不得算作成功。

## 选择执行形态

读取 [agent-routing.md](references/agent-routing.md)，选择最小足够方案：

- 单代理：一个模块、一个清晰结果、低风险改动。
- 原生子代理：多个有界、可独立完成的探索、资料、测试或审查流。
- Worktree：两个写入任务确实需要隔离，或计划任务必须远离当前未完成工作。

不要为了显得专业而固定启动很多代理。子代理会增加等待和协调成本。

## 编排规则

1. 先定义主任务的 Goal、共享事实和不允许改变的边界。
2. 使用原生 `spawn_agent` 启动有界任务；数量由真实任务需要和原生工具接受情况决定，不固定模型或数量。
3. 优先并行只读工作：代码定位、架构分析、官方资料、安全审查、测试缺口和日志分析。
4. 同一 checkout 默认只有主代理写入。并行写入必须使用不同 Worktree、分支、文件所有权和整合顺序。
5. 给子代理最少且充分的上下文，不发送预期答案。要求它先确认任务可读，再引用文件、命令或其他证据。
6. 使用 [result-contract.md](references/result-contract.md) 约束精炼结果，主代理核对证据后再决定是否实施。
7. 汇总后只把真正影响项目的事实写入代码、测试或精简文档，不创建可见任务来清理子代理。

## 推荐职责

- Explorer：只读定位代码、数据流和影响面。
- Architect：只读比较边界、接口和迁移方案。
- Reviewer：只读查找正确性、安全和测试风险。
- Verifier：运行验证并报告证据，不修改产品源码。

这些是临时任务职责，不要求安装或创建自定义 Agent。模型、推理和并发保持 Codex 官方默认。

## 输出

报告执行形态、代理分工、任务接收确认、写入所有权、结果摘要和主代理最终决定。
