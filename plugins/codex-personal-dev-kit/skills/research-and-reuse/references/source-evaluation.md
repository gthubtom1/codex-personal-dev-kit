# 外部来源评估

## 来源优先级

1. 官方文档、标准、规范和安全公告。
2. 官方示例、原作者或维护组织仓库。
3. 活跃、测试充分、许可证清楚的成熟开源项目。
4. 能提供可核验证据的高质量技术资料。

## 候选检查

对每个进入最终比较的候选检查：

- 解决的问题是否与当前项目一致，而不是只看名称相似。
- 语言、框架、平台、运行时和数据模型是否兼容。
- 最近维护、发布、Issue 和安全公告是否显示仍可依赖。
- 许可证是否允许当前用途，是否要求署名、公开修改或传递相同许可证。
- 安装脚本、原生二进制、传递依赖和网络行为是否可接受。
- 是否有测试、示例、迁移说明和稳定接口。
- 接入后新增多少长期复杂度和退出成本，能否替换、降级或删除。
- 是否会改变隐私、成本、兼容性、性能或用户可见行为。

不要用 Star 数直接判断质量。无法确认许可证、安全或维护状态时，把不确定性作为采用阻断项，而不是省略。

## 采用层级

- 学习设计：只提取公开思想、状态机、接口或测试场景。
- 使用依赖：经过许可后加入锁定版本，并记录用途和退出方案。
- 适配源码：仅复制许可证明确允许且范围最小的部分，保留来源和归属。
- 原型验证：在隔离临时目录验证方向，默认不进入产品代码。
- 自行实现：外部方案不兼容、风险高或复杂度大于收益时采用。
