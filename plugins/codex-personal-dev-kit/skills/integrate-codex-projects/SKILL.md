# Integrate Codex Projects

当前打开的项目是唯一目标项目；只有用户明确指定的其他路径可以作为只读来源。融合的是产品能力和清晰接口，不是把文件夹或 Git 历史直接混在一起。

## 启动边界

1. 确认目标项目就是当前 Codex 工作文件夹。用户未明确目标时停止写入，只做方案说明。
2. 在分析来源前，先只读恢复目标项目事实：读取目标项目的 `AGENTS.md`、PROJECT、FEATURES、STATUS、相关架构与测试、Git 状态和受影响功能入口，明确必须保持的现有行为、冲突点和回归范围。
3. 列出用户明确指定的来源项目绝对路径。不得扫描 `projects` 下其他兄弟项目，也不得根据名称自行挑选来源。
4. 读取每个来源项目自己的 `AGENTS.md`、必要文档、Git 状态、许可证和相关实现；默认只读，不修改、不提交、不运行未知脚本。
5. 如果来源包含第三方代码或许可证不明，调用 `$research-and-reuse` 完成来源评估。

## 融合流程

1. 先定义最终用户结果：保留、替代、新增和明确不做的行为。
2. 阅读 [compatibility-matrix.md](references/compatibility-matrix.md)，比较功能、技术栈、数据、身份权限、接口、依赖、UI、许可证、测试和运行方式。
3. 选择最小集成方式：
   - 重新实现能力并保持来源只读；
   - 提取稳定接口或共享模块；
   - 经许可后适配最小源码；
   - 暂时通过本地进程/API 连接；
   - 先做可丢弃原型验证。
4. 默认不合并 Git 历史，不整包复制目录，不让目标项目长期直接引用来源项目的内部文件路径。
5. 读取 [integration-safety.md](references/integration-safety.md)，建立当前变更契约、Feature ID 映射、数据迁移/回退方案和完整接线检查。
6. 一次只实现一个可观察的纵向切片；来源项目保持只读，目标项目只有一个源码写入者。
7. 验证目标项目原有功能、移入能力和两者邻接流程，创建目标项目本地检查点。

## 权限

- 读取用户明确指定的本地来源项目用于比较，可以在当前请求范围内自动进行。
- 读取未指定兄弟项目、修改来源项目、复制大量源码、安装新生产依赖、迁移真实数据、连接私有远程仓库、合并 Git 历史或改变重大架构前必须询问。
- 不自动 push、pull、merge、rebase、发布、部署或删除任一项目内容。
- 目标项目以外的已有 Git 状态、未提交工作和用户数据必须保持不变。

## 文档与交接

融合期间可使用一个覆盖更新的 `.codex/integration-plan.md`，包含目标、来源路径、能力映射、当前切片和停止条件；完成后删除，或把真正长期事实写入 FEATURES、ARCHITECTURE 和必要 ADR。禁止建立永久融合日志或复制来源项目文档。

## 输出

用普通中文说明：目标项目、只读来源、最终产品结果、兼容性阻断、推荐融合方式、当前最小切片、需要授权事项、验证和回退方式。不要要求零基础用户选择 Git 或文件级合并策略。
