# 融合安全规则

## 目标仓库

- 当前打开的目标项目是唯一默认写入仓库和最终回退历史。
- 来源项目保持只读；如果确需修改来源，必须另开明确任务和独立检查点。
- 不把 Worktree、分支或 Git 历史合并当作产品融合本身。

## 功能保护

1. 给目标项目现有能力保留稳定 Feature ID。
2. 为移入能力创建新的 Feature ID，并记录原来源与新的接线入口。
3. 在修改前补足目标项目关键行为测试。
4. 检查 UI、API、状态、持久化、后台处理、设置和错误路径是否全部接通。
5. 数据变化必须有备份、可重复迁移和失败恢复路径。

## 实现策略

- 优先在目标项目的现有架构中重新表达能力。
- 共享模块必须有稳定接口，不能依赖来源项目的内部目录布局。
- 避免一次性改写目标项目或整包复制来源项目。
- 每个纵向切片单独验证和创建本地检查点。
