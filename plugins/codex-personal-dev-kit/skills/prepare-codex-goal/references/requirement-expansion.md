# 需求拓展的 20 个维度

逐项快速检查，不要求每个 Goal 都实现全部维度。把发现标为“本次必需、建议纳入、以后再做、明确不做”。

1. 用户与角色：谁使用，技术水平和权限是什么。
2. 核心结果：用户完成什么，而不只是系统执行什么动作。
3. 主流程：从入口到成功结果的完整步骤。
4. 空、加载、错误、取消、重试和离线状态。
5. 数据模型、格式、校验、唯一性和生命周期。
6. API、事件、文件格式及跨模块合同。
7. 身份认证、授权和最小权限。
8. 隐私、敏感数据、保留期限和日志脱敏。
9. 安全威胁、恶意输入、上传和供应链风险。
10. UX、一致性、响应式和无障碍。
11. 性能、容量、并发和成本上限。
12. 可靠性、幂等、超时、重试和故障隔离。
13. 可观测性：日志、指标、追踪和告警。
14. 配置、环境差异、功能开关和密钥来源。
15. 依赖、版本兼容、许可证和退出方案。
16. 数据迁移、回填、双写、回滚和备份。
17. 测试层级、测试数据和验收证据。
18. 发布、灰度、部署、回退和运维责任。
19. 文档、支持、故障手册和所有权。
20. 后续扩展、明确非目标和防止过度设计的边界。

## 使用规则

- 发现遗漏不等于自动扩大范围。
- 影响正确性、安全、数据完整性或验收的内容通常属于本次必需。
- 只提高未来便利但没有当前证据的内容通常进入以后再做。
- 对零基础用户给出推荐默认值，并说明忽略该项的实际后果。

## 零基础项目的固定澄清

- 用户说“手机和电脑都能用”时，必须确认是“都能打开”还是“共享同一份数据”。推荐第一版做响应式本地应用和导出备份；跨设备同步另列目标，因为它会引入账号、服务器、冲突、隐私和费用。
- 离线验收必须覆盖：在线首次打开、断网、关闭重开、增删改查、统计、导出和存储失败提示；只验证“断网能新增”不够。
- 必须说明本地数据保存位置、导出格式、导入恢复和清理浏览器后的损失边界；Git 能恢复代码，不能恢复浏览器里的用户数据。
- 财务场景必须明确金额使用整数最小单位而不是浮点数、货币和小数位、收入/支出正负、月份时区、月初月末、空月份、舍入规则，以及 CSV/JSON/Excel 的编码、引号、换行和公式注入防护。
- 第一个功能检查点前，模板中的 `Not yet confirmed` 必须替换为真实产品事实、架构边界、可复现命令、Feature 验证入口和 `STATUS` 下一步；占位文档不能进入首个功能检查点。
